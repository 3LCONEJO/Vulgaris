Nextflow / EXPORT SEURAT DATA

EXPORT SEURAT DATA

tipo/procesojob/customenv/scatac_full

nf/modules/b_general/export_seurat_data.nf

Envuelve B_general/1_R/export_seurat_data.r — el primer paso real de todo el pipeline (exporta peaks/barcodes/metadata con rutas de fragmentos a partir del objeto Seurat integrado).

El proceso completo

process EXPORT_SEURAT_DATA {
    label 'scatac_full_env'
    label 'light_job'
    publishDir "${params.project_root}/2_data/${params.data_date}/B_general", mode: 'copy'

    output:
    path "seurat_metadata_with_fragments.tsv", emit: cell_data
    path "sample_fragment_mapping.tsv",         emit: fragment_mapping
    path "integrated_peaks.bed"

    script:
    """
    Rscript ${params.project_root}/1_scripts/B_general/1_R/export_seurat_data.r \\
        ${params.seurat_object_path} .
    """

    stub:
    """
    touch seurat_metadata_with_fragments.tsv sample_fragment_mapping.tsv integrated_peaks.bed
    """
}

Pieza por pieza

  • label 'scatac_full_env' / label 'light_job' — un label es una etiqueta arbitraria (cualquier nombre) que después nextflow.config usa para decidir qué conda env activar y qué recursos de LSF pedir (ver Nextflow Config). Un proceso puede tener varios labels a la vez — aquí uno dice “qué entorno” y otro “cuántos recursos”, cosas independientes.
  • publishDir — copia (o symlink) los outputs declarados hacia una ruta legible por humanos, además de donde Nextflow los cachea internamente (work/). Es la única razón por la que 2_data/<fecha>/B_general/ sigue teniendo la misma pinta de siempre — Nextflow por dentro guarda todo en work/xx/yyyy.../, con nombres de hash, no en esa ruta.
  • output: con emit:** — declara qué archivos produce el proceso. emit: cell_data le pone un nombre a ese output específico, para poder referenciarlo después como EXPORT_SEURAT_DATA.out.cell_data desde el workflow (ver Workflow & Main). El tercer output (integrated_peaks.bed) no tiene emit: porque nada de este piloto lo vuelve a leer — sigue publicado, pero nadie lo necesita como input.
  • Sin input: — es el ÚNICO módulo de este piloto sin dependencias de otro proceso. En vez de recibir un canal, lee params.seurat_object_path directo (un parámetro global de nextflow.config, no un archivo que pasó por otro proceso).
  • script: — el bloque real que se ejecuta. Es exactamente la misma llamada a Rscript que ya se hacia previamente — Nextflow no reescribe la lógica, solo la orquesta — fue un principio de diseño explícito, no casualidad: migrar sin tocar ni un script.
  • stub: — bloque alternativo, ver Stub Run.

Por qué el . al final del Rscript ... call

export_seurat_data.r acepta [seurat_object_path] [out_dir] como argumentos posicionales (ver el propio script). El . le dice “escribe aquí mismo, en el directorio de trabajo de este proceso” — eso es lo que publishDir/output: después recogen.
