Nextflow / MERGE QC STATES

MERGE QC STATES

tipo/procesojob/light

nf/modules/a_pycistopic/merge_qc_states.nf

Junta los N state que salen de las corridas paralelas de QC_RUN_ONE_SAMPLE (una por muestra) en UN solo state antes de pasárselo a QC_PLOTS_THRESHOLDS. Es exactamente el mismo patrón que merge_cistopic_states.nf (ver MERGE CISTOPIC STATES para el detalle completo de stageAs con patrón y cp).

process MERGE_QC_STATES {
    label 'light_job'
    input:
    path states, stageAs: 'sample_state_*'
    output:
    path "state", emit: state
    script:
    """
    mkdir -p state
    for d in sample_state_*; do
        cp -rnL "$d"/. state/
    done
    """
}

En pycistopic.nf:

QC_RUN_ONE_SAMPLE(qc_samples, QC_GENERATE_COMMANDS.out.state.first())
MERGE_QC_STATES(QC_RUN_ONE_SAMPLE.out.state.collect())
QC_PLOTS_THRESHOLDS(MERGE_QC_STATES.out.state, cell_data, fragment_mapping)

Por qué hace falta: cada corrida paralela de QC_RUN_ONE_SAMPLE partió del mismo state_in (con consensus_regions.bed/tss.bed ya en su lugar) e hizo su propio cp -rL state_in state, agregándole solo los archivos QC de SU muestra (state/1_qc/<sample>.pycistopic_qc.log, <sample>.fragments_stats_per_cb.parquet, etc.). QC_PLOTS_THRESHOLDS necesita verlas TODAS juntas en un mismo state/1_qc/ para poder generar plots y calcular umbrales por muestra — de ahí la misma barrera de sincronización que ya se usó para BUILD_CISTOPIC_OBJECTS (collect() no dispara este proceso hasta que las N corridas paralelas de arriba — o cuantas maxForks deje correr a la vez nextflow.config — terminaron todas).
