BINARIZATION TOPIC

tipo/procesojob/mediumenv/pycistopic

nf/modules/a_pycistopic/binarization_topic_qc.nf

Envuelve 08_binarization_topic_qc.py (binarización Otsu/Yen de β, métricas de tópico, anotación por tipo celular). Mismo patrón state/cp y flag condicional (--annot-var) que ya se vio en los módulos anteriores — no hay sintaxis nueva aquí, es un buen ejemplo de que, una vez entendido el patrón state, la mayoría de estos módulos son casi mecánicos de escribir.

Única dependencia real

Necesita el *_cistopic_obj_final.pkl que dejó el paso anterior (MODEL SELECTION UMAP), no el de BUILD CISTOPIC OBJECTS/ COMBINE_MODELS directamente — pero como state va acumulando todo, esto ya está resuelto con solo encadenar state_in desde el proceso correcto en el workflow (ver Workflow & Main).

Mismo bug/fix de publishDir que MODEL SELECTION UMAP — con una vuelta extra

Este módulo tiene el mismo problema de fondo que MODEL_SELECTION_UMAP (ver MODEL SELECTION UMAP para la explicación completa de por qué pattern no matchea una ruta anidada dentro de otro output, y por qué figures_out tiene que ser un directorio hermano de state, no una subcarpeta suya). La vuelta extra aquí: 08_binarization_topic_qc.py siempre le agrega "topic_binarization_qc" a lo que sea que reciba en --figures-dir, sin importar si se le pasa explícito o no (es una línea fija adentro del script, no un default condicional). Por eso el output declarado no es figures_out a secas, sino la ruta real que el script termina usando:

output:
path "state", emit: state
path "figures_out/topic_binarization_qc", emit: figures

publishDir "${params.project_root}/4_figures/${params.run_date}/A_pyCisTopic/topic_binarization_qc", mode: 'copy', pattern: "figures_out/topic_binarization_qc", saveAs: { fn -> '.' }

Y el destino del publishDir YA incluye /topic_binarization_qc al final — saveAs: { fn -> '.' } aplana el CONTENIDO de esa carpeta (los PNGs de otsu/, top3k/, y los *_topic_qc.png/*_topic_umap.png) directo ahí, sin crear un topic_binarization_qc/topic_binarization_qc/ de más.

Consecuencia real de este bug antes de corregirse ([2026-09-08/09]): sin --figures-dir explícito, el script resolvía su propio default leyendo el symlink 3_output/NEW (una ruta absoluta del filesystem real, no relativa a este proceso) — y ese symlink apuntaba a una corrida vieja (2026-08-21). La corrida real de producción (2026-09-07) terminó sobrescribiendo los PNGs merged_* de esa corrida vieja (mismos nombres de archivo, sin git/backup de por medio). Se recuperaron moviendo los 4 archivos a mano a su carpeta con fecha correcta — pero el contenido original de la corrida vieja para esos 4 archivos puntuales ya no existe. Moraleja para cualquier script nuevo de este pipeline: nunca confiar en que un default “inteligente” que lee un symlink compartido del filesystem coincida con lo que Nextflow cree que está pasando — pasar SIEMPRE --figures-dir/--out-dir explícito desde el .nf, aunque sea redundante con el default del script.
