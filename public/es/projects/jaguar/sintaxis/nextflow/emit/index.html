Nextflow / emit:

emit:

tipo/sintaxislang/nextflow

Nextflow recibe un archivo bajo su nombre clave, pero para no confundirse le pasa un nombre que puede ser el mismo u otro a bash, esto para ser más organizados con los inputs y outputs del workflow del pipeline.

Ojo — un ajuste a lo de arriba

El nombre de emit: no viaja a bash. Bash nunca lo ve. Es un nombre que existe solo del lado de Nextflow, para que el workflow pueda referirse a esa salida después. La idea de fondo sí es la tuya: sirve para no confundirse cuando un proceso saca varias cosas.

output:
path "seurat_metadata_with_fragments.tsv", emit: cell_data
path "sample_fragment_mapping.tsv",        emit: fragment_mapping

Y en el workflow, en vez de contar posiciones, lo llamas por su nombre:

EXPORT_SEURAT_DATA()
cell_data        = EXPORT_SEURAT_DATA.out.cell_data
fragment_mapping = EXPORT_SEURAT_DATA.out.fragment_mapping

Sin emit: eso sería EXPORT_SEURAT_DATA.out[0] y .out[1], y el día que agregas una salida nueva en medio, se recorre todo y nada avisa.

El otro emit:

También existe a nivel de workflow completo, con la misma idea — nombrar lo que ese workflow saca hacia afuera:

workflow PYCISTOPIC {
    ...
    emit:
    state = DARS_GENE_ACTIVITY.out.state
}
