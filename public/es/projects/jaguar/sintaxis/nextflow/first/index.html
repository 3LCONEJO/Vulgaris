Nextflow / first()

first()

tipo/sintaxislang/nextflow

El problema que resuelve

Un canal normal es una cola: cada item se consume una sola vez y se gasta. Eso está bien cuando cada item dispara su propia ejecución, pero rompe cuando un proceso que corre UNA vez tiene que alimentar a N ejecuciones paralelas.

QC_RUN_ONE_SAMPLE(qc_samples, QC_GENERATE_COMMANDS.out.state.first())

Aquí hay dos inputs y se comportan distinto:

  • qc_samples — canal de cola con ~20 items (uno por muestra, gracias al .splitCsv()). Cada item dispara una ejecución de QC_RUN_ONE_SAMPLE con su propio sample_id/fragment_path.
  • QC_GENERATE_COMMANDS.out.state — la carpeta con consensus_regions.bed/tss.bed que ese comando necesita como rutas fijas. Pero QC_GENERATE_COMMANDS corre UNA sola vez y emite state UNA sola vez.

Sin .first(), ese canal de un solo uso se gastaría en la primera de las ~20 ejecuciones, y las otras 19 se quedarían esperando para siempre un segundo item que nunca llega.

Qué hace

Convierte el canal en un value channel: un valor reusable, que se puede leer infinitas veces sin gastarse. Así las ~20 ramas reciben cada una su propio fragment_path distinto pero la MISMA copia de state.

Dónde más aparece

El patrón se repite en todo el pipeline, cada vez que un proceso de una sola corrida (state, tss_bed, cell_data, …) alimenta a un proceso que se ramifica por muestra. Ver Workflow & Main, sección .first() — de canal de un solo uso a valor reusable.

Ver también

  • collect() — la operación espejo: cierra el abanico que esta abre.
  • input — por qué el input: es quien decide cuántas veces corre un proceso.
